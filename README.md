# research-inferencing

Research notes on LLM/ML inference systems.

## Documents

- **[Recursive Models That Learn at Test Time — Three Recursions and the Fixed Point That Keeps Them Honest](recursive-self-improvement.md)** *(2026-09)* — the recursive deepening of the self-improvement doc: one fixed-point equation with three loop variables — depth recursion on latents (looped transformers, Huginn, Mixture-of-Recursions, Ouro, HRM/TRM and the ARC Prize ablation), weight recursion (TTT layers, Titans, LaCT chunking, MesaNet-to-convergence, per-task LoRA), and learner recursion (self-referential weights, HOPE, meta-trained TTT, SEAL, Darwin Gödel Machine); why every recursion needs a grounding signal outside its loop variable (model collapse as the ungrounded fixed point); a prelude/looped-core/coda model recipe with GDN/TTT layers and learned exit; recursion budgets as a per-request routing knob on the fleet; tiny recursive specialists as agent tools; recursion-specific invariants, residual canaries, and build order.
- **[Designing a Runtime Self-Improving Model — Test-Time Training Across Four Loops](runtime-self-improvement.md)** *(2026-08)* — survey + design for models that improve while serving: the four-loop taxonomy (context artifacts, fast-weight state, per-task gradients, sleep consolidation), the TTT evidence base (TTT layers/Titans, TTT-NN, ARC TTT, SEAL, Cartridges, TTRL, GEPA/ACE), the verified-reward hierarchy and poisoning surface, and the mapping onto the fleet — cartridges as trained KV in the existing block store, nightly LoRA consolidation on idle Macs, the Spark lab bench as learner plane, eval-gated artifact promotion.
- **[Lessons from SGLang — What Transfers to an Apple-Silicon Engine and a Heterogeneous Fleet](sglang-lessons.md)** *(2026-08)* — deep read of SGLang at head: its MLX backend's two-in-flight lazy-graph decode chain, FutureMap overlap scheduling, the HiCache L2-private/L3-shared contract and content-addressed store playbook, kv_canary fingerprints, the Rust model gateway's routing policies (and its open-loop blind spot), dead jump-forward code, DSpark's knapsack speculation, and NGRAM external-corpus drafting for coding agents.
- **[A Heterogeneous Inference Fleet — M5 Macs + CPU Servers + DGX Sparks](fleet-architecture.md)** *(2026-08)* — scale-out serving design for agentic workloads: mixed-phase M5 replicas, a content-addressed KV block store on the CPU fleet (the Mooncake role), Sparks as prefill service / P/D cells / frontier island, and prefill/decode separation as a measured per-turn routing threshold rather than a static topology.
- **[oMLX Code Study — Inside a Production LLM Inference Engine for Apple Silicon](omlx-code-study.md)** *(2026-08)* — deep read of [jundot/omlx](https://github.com/jundot/omlx) v0.6.4 (~225K LOC): external chunked prefill over mlx-lm continuous batching, time-domain decode fairness, memory-admission control, the metadata-only paged KV cache with RAM/SSD tiers and hybrid-model state checkpointing, Lightning MTP / DFlash / SpecPrefill speculation, oQ quantization, custom Metal kernels, the multi-Mac (and Mac+CUDA) pipeline cluster — and the centerpiece: prefill split across GPU + both ANE dies + CPU via private APIs (+36–46% prompt throughput, decode unchanged).
- **[Inference Engine Architecture — and Whether Engines Can Use All the Hardware (CPU/GPU/NPU/ANE) for Max Throughput](inference-engine-architecture.md)** *(2026-08)* — anatomy of datacenter serving engines (vLLM, SGLang, TensorRT-LLM, Dynamo) and on-device engines (llama.cpp, MLX, Core ML/ANE, ONNX Runtime, OpenVINO, Ryzen AI); the prefill/decode roofline physics; why "run it on every unit" usually loses to saturating the bandwidth-dominant unit; and the real heterogeneous wins (KTransformers CPU+GPU MoE, NPU-prefill + iGPU-decode, disaggregated serving, stage splits).
